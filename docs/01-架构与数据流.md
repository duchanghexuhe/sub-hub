# 01 — 架构与数据流

## 容器架构

```
                         ┌─────────────────────────── sub-hub 容器 (NAS:8399) ────────────────────────────┐
                         │                                                                                │
 机场订阅 A/B/C... ──────▶  fetcher ──▶ parser ──▶ cleaner ──▶ templater ──▶ data/out/                    │
 (定时+手动)                │            (统一节点模型)  (过滤/分类)    (jinja2)        │                          │
                         │     ▲                                          ▲    │                        │
                         │     │  rulesync（规则缓存镜像，永不失效）          │    │                        │
 blackmatrix7 等 ────────┼─────┴──────────────────────────────────────────┘    ▼                        │
 上游规则仓库             │                                            FastAPI 分发端点 ──▶ 客户端拉取     │
                         │  purity（纯净度检测：内置 mihomo 探测实例 127.0.0.1:9095）      (Verge/Shadowrocket)│
                         │  scheduler（APScheduler：订阅刷新/规则镜像/纯净度扫描）         │                    │
                         │  store（SQLite + Fernet 加密凭据）  ◀──── web UI（单页管理）◀──┘                    │
                         └────────────────────────────────────────────────────────────────────────────────┘
```

### 模块职责

| 模块 | 职责 | 关键点 |
| --- | --- | --- |
| `fetcher` | 定时抓取各启用订阅；解析 `subscription-userinfo` 响应头（流量/到期） | 固定 Clash UA 拿 YAML；快照落盘 `data/cache/` |
| `parser` | 解析为统一节点模型 | 主路径 Clash YAML；兜底 base64 订阅（ss/vmess/vless/trojan/hysteria2/tuic URI） |
| `cleaner` | 假节点过滤、地区/属性分类、重名消歧 | 规则见 02 文档；白名单日志可查被滤节点 |
| `templater` | 渲染 mihomo YAML 与 Shadowrocket conf | jinja2 模板 + 分组计算；分组语义见 02 文档 |
| `mirror`（可选，默认关闭） | 渲染成功且内容变化时，把产物推送到公网静态镜像，供外网客户端拉取 | 支持 CF Workers+KV（带 token 鉴权，推荐）/ GitHub 公库随机路径；推送含凭证文件属敏感动作，需用户显式配置开启；推送失败不影响主链路 |
| `rulesync` | 定时拉取上游规则集 → 缓存镜像 → 供客户端 RULE-SET 引用 | **永不失效**：上游失败沿用旧缓存；镜像内置基线（首次部署离线可用） |
| `purity` | 逐节点出口 IP 检测（ASN/住宅机房/风险信号） | 内置 mihomo 探测实例；详见 03 文档 |
| `store` | SQLite（订阅表/节点快照/检测记录）+ 订阅 URL Fernet 加密 | 密钥 `data/secret.key` 权限 0600 |
| `scheduler` | 三类定时任务：订阅刷新（默认 30min）、规则镜像（6h）、纯净度扫描（每天 04:00） | 间隔均可配置 |
| `web` | FastAPI：分发端点 + 管理 API + 单页 UI | 分发链接带 token；UI 见 03 文档 |

## 端到端数据流

### 流程 1：订阅 → 配置（核心链路）

1. scheduler 触发（或 UI/API 手动）→ fetcher 逐订阅抓取，原始内容存 `data/cache/<sub_id>-<ts>.yaml`（保留最近 3 份）。
2. parser 输出统一节点模型：`Node{ name, type, server, port, 凭据字段…, source_sub, region?, residential?, iplc?, rate? }`。
3. cleaner：滤假节点 → 识别地区/属性 → 重名消歧（`原名 [机场别名]`）。
4. templater：按 02 文档的分组语义计算各组成员（地区组、Claude 组、AI 组…），渲染两份产物 + 一致性校验（两格式的组/规则覆盖必须等价，校验失败拒绝发布）。
5. 产物写入 `data/out/`（原子替换：先写 `.tmp` 再 rename），记录版本号与节点数 diff；UI 显示「配置已更新 ±N 节点」。
6. 客户端拉取时，分发端点附加 `subscription-userinfo` 头（来自 fetcher 解析的流量/到期），Clash Verge / Shadowrocket 即可显示用量。

### 流程 2：规则镜像

- rulesync 每 6h 拉取 02 文档规则清单（blackmatrix7 的 Clash `.yaml` 与 Shadowrocket `.list` 双格式），缓存到 `data/rules/`。
- 生成配置里的 RULE-SET / rule-providers 全部指向 `http://<nas>:8399/rules/<name>.yaml|.list`，客户端永远只碰 NAS。
- 失败路径：上游超时/404 → 沿用旧缓存并在 UI 标记「规则源 N 小时未更新」；容器镜像内打包一份基线规则，保证首次部署、上游断更时链路不断。

### 流程 3：纯净度检测（旁路，不阻塞分发）

每天 04:00（低峰）+ 手动触发：purity 启动内置 mihomo 探测实例（`external-controller: 127.0.0.1:9095`，仅容器内），加载全部真实节点 → 逐节点经该代理请求 ip-api → 结果写库 → 更新 UI 报告与 Claude 组建议排序。详见 03 文档。检测实例崩溃不影响主链路（分发用的配置不依赖检测实例）。

## 失败路径与安全网

| 故障 | 行为 |
| --- | --- |
| 某订阅抓取失败/超时 | 保留该订阅上次成功快照继续参与渲染；UI 标黄「N 小时未更新」；不清空其节点 |
| 订阅 token 失效（401/403）或返回 0 个有效节点 | 沿用旧配置继续分发 + UI 告警「订阅失效，当前为陈旧配置」；**拒绝发布空节点配置** |
| 上游规则集全部不可达 | 用缓存旧规则 + 内置基线；仅当缓存与基线都缺失时才拒绝发布（理论上不可能） |
| 单节点解析失败（新协议/字段异常） | 跳过并记录日志，不阻塞整体；UI「解析异常节点」列表可见 |
| 两格式一致性校验失败 | 拒绝发布新配置，沿用上一版；记录 diff 供排查 |
| mihomo 探测实例启动失败 | 纯净度报告标记 unavailable；主链路无感 |
| 渲染产物非法 YAML/conf | 渲染后先本地 parse 校验，失败即回滚上一版 |

总原则：**分发可用性 > 数据新鲜度**。任何环节故障都退化为「继续用上一份好配置」，绝不向客户端下发坏配置或空配置。

## 部署形态

- compose 项目 `/share/Container/sub-hub/`：单容器 `sub-hub:latest`，端口 `8399:8399`，挂载 `data/`，`restart: unless-stopped`。
- 镜像：`python:3.12-slim` + FastAPI/uvicorn/jinja2/apscheduler/sqlalchemy/pyyaml + 内置 mihomo 二进制（探测用）。本地 Windows 构建后 `docker save | ssh nas docker load` 直传（沿用 movieclaw 流程 B 的传输惯例），或 NAS 上经代理构建。
- 健康检查从 NAS 宿主机 `curl http://127.0.0.1:8399/api/health`（容器内不留 curl/wget）。
- 部署前校验宿主 8399 未被占用（`ss -tlnp | grep 8399`）。
