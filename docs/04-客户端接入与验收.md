# 04 — 客户端接入与验收

## 1. 接入步骤

### Clash Verge（Windows 本机）

1. 复制 UI 上的订阅链接 `http://192.168.31.10:8399/sub/<token>/clash.yaml`。
2. Clash Verge → 订阅 → 新建：粘贴链接，更新间隔设 30~60min。
3. 若之前手动改过 Verge 全局配置，关掉「使用订阅全局配置」的冲突项（混合端口已被模板对齐为 7897，与现状一致）。
4. 选中该订阅，检查代理页分组齐全（🛑 Claude 专用等），手动锁定 Claude 节点一次。

### Shadowrocket（iOS，在家 WiFi 下）

> **产物选择（2026-09-29 起变更）**：SR 主推 `shadowrocket.yaml`（Clash 兼容格式，
> 规则全内联）。原因：SR 原生 conf 无法表达 VLESS REALITY（公钥/短 ID 参数被其
> 解析器静默丢弃，导致 REALITY 节点全部握手超时）；conf 产物保留仅为兼容老习惯，
> REALITY 机场下不可用。

1. 复制 `http://192.168.31.10:8399/sub/<token>/shadowrocket.yaml`。
2. Shadowrocket → 配置 → 添加（或「扫码」UI 生成的二维码）——SR 兼容 Clash YAML，
   节点、分组、规则一并导入。
3. 确认版本 ≥6.3（anytls 支持）；否则产物中已自动跳过 anytls 节点，其余节点不受影响。
4. 外网使用见下节「外网使用（无公网 IP / 无域名 / 无 VPS）」。

## 2. 外网使用（无公网 IP / 无域名 / 无 VPS，不使用组网 VPN）

先摆清事实：外网设备能直达的只有机场自己的服务器，NAS 不可达。而节点连通性由机场提供（与 NAS 无关），配置和规则导入手机后就地生效——**外网问题的本质只是「更新通道」**，不是「能不能用」。更新通道按三档设计：

### 主方案：公网静态镜像（可选模块 `mirror`，推荐开启）

原理：NAS 把渲染好的配置**推送**到免费第三方静态托管，外网客户端订阅该公网 URL——NAS 不需要任何公网条件，是"推"不是"暴露"。

| 提供方 | 形态 | 鉴权 | 国内直连 | 前置条件 |
| --- | --- | --- | --- | --- |
| **CF Workers + KV（推荐）** | Worker 校验 URL 中 token 后从 KV 返回文件，客户端视角就是一条静态链接 | ✅ token 由 Worker 代码强制校验 | 时好时坏，走代理稳定 | 注册 Cloudflare + 创建 API Token |
| GitHub 公开仓库随机路径 / secret gist | NAS git push，客户端拉 raw 链接 | ❌ 仅靠 64 位随机路径保密（obscurity） | raw.githubusercontent.com 直连不通，**须代理活着** | 复用本机已有 GitHub token |

- 推送时机：每次渲染产物内容变化后自动推（对比 hash，无变化不推）；UI 可手动推、看最近推送状态。
- **凭证告知义务**：配置文件内含全部节点凭证，推到第三方即视为托管给该平台。CF 方案有 token 读取保护、平台可见内容；GitHub 公库方案只有路径保密。用户知晓并选择后开启。
- **死结物理边界**：若机场轮换节点导致代理全死，外网设备直连上述托管都不稳/不通，自动更新失灵——此时回落离线包。此限制无解，任何公网中转都一样（机场自己的订阅域名是唯一保证直连的源）。

### 保底：离线自包含配置（永远可用）

- 产物：`clash-offline.yaml` / `shadowrocket-offline.conf`，规则全内联，单文件 MB 级，本地导入后脱离一切网络条件运行。
- 导入：在家 WiFi 下从 UI 下载，经 AirDrop / 微信文件传输助手 / 数据线 / 邮箱带到外网设备本地导入。
- 适用：未开启镜像模块、镜像临时不通、代理死结三种情况；配置产物页显示「离线包 N 小时未刷新」。

### 国内平台不采用（合规原因）

Gitee Pages / 腾讯云 OSS / 阿里云 OSS 等国内托管虽然直连稳定，但代理节点凭证属敏感内容，放国内平台 = 实名 + 内容审核风险（可能被清理甚至影响账号），不采用。

## 3. 端到端验收清单

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | UI 添加机场订阅（用真实 URL） | 数秒后节点表出现 ~35 个真实节点（41 - 假节点）；「已过滤」区列出剩余流量/官网类节点 |
| 2 | 打开 `http://<nas>:8399/sub/<token>/clash.yaml` | 200，YAML 可解析，proxy-groups 含全部组、rule-providers 全指向 `/rules/` |
| 3 | Clash Verge 导入订阅 | 代理页组齐全；连接页访问 `claude.ai` 命中 🛑 Claude 专用；`chatgpt.com` 命中 🎁 OpenAI；`gemini.google.com` 命中 🤖 Gemini |
| 4 | 访问百度/腾讯等国内站 | 直连（连接页可见 DIRECT） |
| 5 | 故障切换：手动在机场侧或防火墙阻断当前自动选择节点（或选一个劣质节点观察） | ≤2 分钟内 ♻️ 常规自动 `now` 切换到其他节点（mihomo API `GET /proxies/♻️ 常规自动` 观察） |
| 6 | 纯净度扫描 | 报告逐节点列出出口 IP/ASN；抽查 1 个节点在本地经同一节点 `curl ip-api.com` 比对一致 |
| 7 | Claude 组排序 | 美国家宽节点排最前；把某家宽节点在报告里人工核对为机房后无变化（检测以出口 IP 实测为准，不迷信节点名） |
| 8 | 添加第二个机场订阅 | 节点合并、重名带 `[别名]` 后缀、总节点数增加、配置自动重建 |
| 9 | Shadowrocket 导入 conf | 分组与规则命中行为与 Verge 一致（claude.ai → Claude 专用） |
| 10 | 回退：制造一次坏产物（如临时改坏模板） | 发布被校验拦截，客户端拉到的仍是上一版 |
| 11 | 订阅失效演练：URL 改错后刷新 | UI 告警「订阅失效」，分发端点仍返回旧配置 |

## 4. 关键故障场景预期（汇总）

| 场景 | 预期行为 |
| --- | --- |
| 机场节点整批抖动（几分钟） | 备援/自动组按 90~120s 周期自然切换恢复，无需人工 |
| NAS 重启 | 容器 `unless-stopped` 自动拉起；期间客户端沿用本地已缓存配置与规则 |
| 上游规则仓库断更/被墙 | 容器缓存兜底（6h 镜像周期 + 镜像内置基线），客户端无感 |
| 机场悄悄把家宽节点换成机房落地 | 节点总表该行纯净度徽章标红（家宽→机房），提醒重锁 Claude 节点；不自动换 |
| 误删全部订阅 | 拒绝发布空配置，沿用旧配置 + 告警 |
| 手机在外（4G/5G） | 镜像开启时经公网 URL 自动更新（代理活着即生效）；镜像未开/不通时离线包兜底 |
| 验收补充：镜像链路 | UI 开启 mirror → 手动推送成功 → 手机蜂窝网络下更新订阅得新产物；改坏 token 后推送失败有告警且不影响本地分发 |
| 验收补充：离线包可用性 | 设备断开家庭网络（关 WiFi 走蜂窝），导入离线包后 claude.ai 走 Claude 专用、国内站直连、漏网之鱼行为与主版本一致 |
