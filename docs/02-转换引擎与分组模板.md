# 02 — 转换引擎与分组模板

> 本文档是产品核心：节点怎么清洗分类、分组怎么定语义、规则体系怎么组织、两个客户端格式怎么出。

## 1. 节点清洗与分类（cleaner）

### 假节点过滤

正则黑名单（大小写/emoji 容错），命中即剔除：

```
剩余流量|套餐到期|到期时间|重置|官网|官址|网址|续费|订阅|流量|expire|traffic|电报|频道|群|tg|telegram(节点名中)
```

被滤节点不直接丢弃——存入 UI「已过滤节点」列表可查，防误杀。

### 地区识别

三级匹配：国旗 emoji → 中文关键词 → 英文关键词/缩写。映射表内置且可在 UI 补充。覆盖关键词示例（美国）：`🇺🇸 美国 US United States 洛杉矶 圣何塞 硅谷 西雅图 凤凰城 纽约 芝加哥 达拉斯 DMIT Los Angeles San Jose`。

未识别地区的节点归入「🌍 其他」组，不会丢失。

### 属性标记

| 属性 | 关键词 | 用途 |
| --- | --- | --- |
| 住宅/家宽 `residential` | `家庭 家宽 住宅 ISP Home residential` | **Claude 组排序核心依据** |
| 专线 `iplc` | `专线 IEPL IPLC` | 优选参考，展示用 |
| 倍率 `rate` | `x2 x3 2x 3x`（解析为数值） | 展示用；v1 不按倍率过滤（标注在节点名） |
| 探测器偏移 | — | 「尽快到访问官网」类无国旗 ss 节点会被假节点正则命中，无需特判 |

### 重名消歧

多机场合并后同名节点追加 ` [机场别名]` 后缀；机场别名 = 订阅管理里的短代号（如 `kuai`）。

## 2. 分组设计（mihomo proxy-groups）

### 组清单与语义

| 组名 | 类型 | 成员语义 |
| --- | --- | --- |
| 🚀 节点选择 | select | ♻️ 常规自动、各地区组、DIRECT + 全部节点 |
| ♻️ 常规自动 | url-test | 低倍率真实节点：倍率 ≤ max(`SUBHUB_AUTO_MAX_RATE`，默认 1.0，全库最低倍率)；省流——常规流量不走高价档 |
| 🇭🇰 香港 / 🇹🇼 台湾 / 🇯🇵 日本 / 🇸🇬 新加坡 / 🇺🇸 美国 / 🇰🇷 韩国 / 🇬🇧 英国 / 🇩🇪 德国 / 🇺🇸…（**按地区动态生成**） | url-test | filter=该地区正则；无节点的地区不生成 |

| 🧷 Claude 备援 | fallback | Claude 专用同批节点；interval 90s |
| 🎁 OpenAI | url-test | filter=美国节点 |
| 🤖 Gemini | url-test | filter=美国节点 |
| 🐙 Copilot | url-test | filter=美国节点 |
| 🧠 通用 AI | select | [Claude 专用, ⛳ 美国优质, 🎁 OpenAI, 各地区组]——未被单列的 AI 服务与新增 AI 域名的兜底入口 |
| 📲 Telegram | url-test | 全部真实节点（TG 对 IP 敏感度低，追求延迟） |
| 🎬 Netflix / 🏰 Disney+ / 📺 YouTube / 🎵 Spotify | select | 各地区组（流媒体解锁有地区偏好，保持手动） |
| 📢 谷歌服务 / Ⓜ️ 微软服务 / 🍎 苹果服务 | select | 默认值分别为 ♻️ 常规自动 / DIRECT / DIRECT |
| 🎮 游戏平台 | select | Steam/Epic 等聚合，默认 DIRECT |
| 🐟 漏网之鱼 | select | [DIRECT, 🚀 节点选择, ♻️ 常规自动]（默认 DIRECT：兜底=国内优先，该代理流量靠规则链显式归组，鱼组只收长尾；可手动切 🚀 整体回退全代理） |

**稳定性自动收敛**：所有 url-test 自动选路组（♻️ 常规自动 / 各地区组 / ⛳ 美国优质 / 🎁🤖🐙 / 📲 Telegram）
在渲染期剔除 24h 窗口内连续失败判死的节点（组清空时回退原成员，组不空置）；🚀 节点选择
是手动全量列表，不减员。数据来自健康采样自动回灌（`health.stability_index`），
无采样数据时与不融合完全一致。

### Claude 专用组语义（防封号核心）

1. **select 手动锁定**：组内首位即默认选中——由纯净度 + 稳定性自动排序算出（见下 3），
   无需人工挑选；用户仍可点进组里手动钉死某个节点，日常绝不变更 IP。
2. **准入线（劣质节点不如不用）**：有纯净度数据时，仅 `claude_rank = 3`（住宅/家宽/mobile 级出口）的已检测节点可入组；干净中小机房 2、大厂云 1、代理标记 0、未检测节点一律排除。全库无合格节点（未扫描/探测不可用）时回退全量池——mihomo 拒载空组，组不可为空是硬约束。准入只看纯净度、不看稳定性（全库合格节点恰好都判死时，剔除会触发全量兜底反而更糟）。
3. 成员默认排序：无检测数据时按静态序 `美国家宽 → 其他美国节点 → 香港/新加坡家宽 → 其余`；有纯净度数据后按评分降序，住宅 IP 恒在机房 IP 之前；同评分层内再按 24h 稳定性细分——存活优先 → 成功率降序 → 均延升序，连续失败判死者沉底（数据源 `health.stability_index`，渲染期自动回灌，无采样数据时该层不生效）。
4. 备援组 `🧷 Claude 备援` 是 **fallback**（interval 90s, lazy=false）：只共享 Claude 专用的候选池，且**只在当前节点存活探测失败时**才切换——保证「主节点挂了会自救、活着就不动 IP」。
5. 使用建议（写进 UI 提示）：Claude Code 长会话期间不要点进 Claude 专用组切换节点；切换后重开 Claude Code 会话再继续高强度使用。
6. 机场删除某节点导致备援池缩小属正常；绝不自动引入候选池之外的节点补位。

### 测速参数规范（解决「切换滞后」）

所有 url-test / fallback 组统一参数，与机场默认对比：

| 参数 | 机场默认 | 本模板 | 说明 |
| --- | --- | --- | --- |
| `interval` | 86400 / 7200 | **120**（Claude 备援等关键组 **90**，lazy=false） | 故障最多 2 分钟被发现并切换 |
| `tolerance` | 无 | **40** (ms) | 防延迟抖动导致来回切换 |
| `max-failed-times` | 默认 5 | **3** | 连续 3 次失败即标记不可用 |
| 探活 URL | google 204 | **`http://cp.cloudflare.com/generate_204`** | 部分节点对 google 探活不友好 |
| `timeout` | 默认 5000 | **3000** | 快速判死 |

假节点过滤本身就是快速切换的保险：杜绝自动组选中「剩余流量」占位节点导致境外全断的已知坑。

## 4. 双格式输出

### mihomo YAML（主，Clash Verge）

- 全局段对齐本机现状：`mixed-port: 7897`、`external-controller: 127.0.0.1:9097`、`mode: rule`、`unified-delay: true`、`tcp-concurrent: true`。
- DNS：fake-ip 模式（沿用机场自带 DNS 思路），nameserver 国内 DoH（`doh.pub` / `alidns`），`fake-ip-filter` 补充局域网与国内大厂域名；`geodata-mode` 不依赖（规则全走 rule-providers）。
- Sniffer：`sniffer.enable: true` + `parse-pure-ip`，嗅探 HTTP（80/8080-8880）/TLS/QUIC（443/8443）。浏览器 DoH/安全 DNS、ECH 或 App 自带解析产生的裸 IP 连接不带域名，无嗅探时全部域名规则失效、直接落「漏网之鱼」（2026-09-28 校准：claude.com 实测落鱼案例）；`skip-domain` 排除 Apple 推送与米家。
- 分组与规则链见上文；`rule-providers` 全部 `type: http, url: http://<nas>:8399/rules/…, interval: 21600`（客户端侧再缓存一层；21600=6h，拉取失败最迟 6h 自愈）。规则链最前端有内建 **LAN 直连护栏**（IP-CIDR 四段私网 + no-resolve）：mihomo 拉 provider 的请求同样过规则引擎，若无护栏，内核启动时规则集全空 → 拉取请求落 MATCH 走代理 → 机场无法回源内网 NAS → 全部规则集空转（2026-09-28 claude.com 落漏网之鱼实测案例）。

### SR conf（次）

- `[Proxy]` 段：节点逐条转换；vless/trojan/ss/hysteria2 直映；**anytls 仅 SR ≥6.3 支持**——低于该版本的客户端导入时自动跳过 anytls 节点（conf 生成器提供 `--skip-anytls` 开关，默认开启并在 UI 显示受影响节点数）。
- `[Proxy Group]` 段：与 mihomo 组一一同名同语义（`select` / `url-test` / `fallback`，参数用 `url=…, interval=120, tolerance=40` 形式）。
- `[Rule]` 段：`RULE-SET,<name>,<组名>`，规则文件由本容器以 `.list` 格式托管（blackmatrix7 原生 SR 格式 + 自维护 claude-extra.list）；最前端同 mihomo 前置内建 LAN 直连护栏四条。
### 产物一致性校验

- 解析回读两份产物，确认组数、规则数等价，不等价拒绝发布。
- 产出一致性校验通过后，共发布 **4 个端点**：`clash.yaml`、`shadowrocket.conf`（主版本，规则引用 NAS）+ `clash-offline.yaml`、`shadowrocket-offline.conf`（离线版，见下）。

### 离线自包含版（外网主方案）

与主版本的唯一区别：**规则全部内联**，不引用 NAS 的 RULE-SET / rule-providers URL。

- mihomo 离线版：`rule-providers` 改为 `type: inline`（payload 直接嵌入 YAML）；分组与规则链完全不变。
- SR 离线版：`.list` 规则内容直接展开进 `[Rule]` 段；单文件 MB 级，本地导入即可在任何网络运行（微信/AirDrop 传输无压力，但二维码扫码不可用）。
- 定位：**外网唯一日常通道**（用户拒绝组网 VPN、无公网条件）。出门前或回家后在 UI 导出一次，通过任意文件传输方式带到外网设备本地导入（SR 支持 Files 本地配置，Verge 支持 Local 配置）。
- 主版本在外网并非不可用：Clash Verge（mihomo）与 SR 都会把拉取过的规则缓存到本地磁盘——只要曾在家里成功加载过一次，外网下规则继续生效，只是不再自动更新。

## 5. 版本与回退

- `data/out/` 保留最近 5 个版本的产物，任何发布故障可一键回退（UI 按钮 / API）。
- 每次发布记录版本号、节点数、与上一版的 diff 摘要（新增/消失/改名节点），UI 时间线可见。
