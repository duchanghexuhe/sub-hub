# 03 — 订阅管理、存储与纯净度检测

## 1. 存储与安全

- **SQLite** 单库 `data/subhub.db`，三张主表：
  - `subscriptions`：name(别名)、url(**Fernet 密文**)、enabled、last_fetch_at、last_fetch_status、userinfo(流量/到期)
  - `node_snapshots`：每次刷新的节点快照（地区/属性/所属订阅/是否被滤）
  - `purity_results`：节点 → 出口 IP / ASN / org / 类型(住宅|机房|移动) / hosting / proxy 信号 / 检测时间
- 订阅 URL 加密：Fernet，密钥 `data/secret.key`（0600，首次启动生成）。UI 展示时打码（仅尾 6 位）。
- **密钥与订阅 URL 不进入对话、不进入日志、不进入配置产物**。分发链接形如 `http://<nas>:8399/sub/<32hex>/clash.yaml`，token 首次启动随机生成，UI 可复制/重置。
- 日志规范：不打印完整订阅 URL（打码到 host）、不打印节点凭据字段。

## 2. 管理 API 契约（签名与语义）

```
GET    /api/health                     存活 + 各定时任务上次执行状态
GET    /api/subs                       列表（URL 打码）
POST   /api/subs                       {name, url, enabled} 新增并立即抓取验证（格式不对直接报错）
PATCH  /api/subs/{id}                  启停/改名
DELETE /api/subs/{id}                  移除并重算配置
POST   /api/refresh                    {sub_id?: int} 手动刷新（缺省=全部）→ 触发完整链路，返回版本号
GET    /api/nodes                      ?region=&tag=&sub_id= 节点列表（含属性、纯净度摘要、被滤原因）
GET    /api/purity/report              全量报告（按 Claude 适配度排序）
POST   /api/purity/scan                {full?: bool} 手动触发扫描（缺省=仅新增/未测节点）
GET    /api/config/preview?fmt=clash|sr  当前产物预览（纯文本）
POST   /api/config/rollback            {version: int} 回退到历史产物
GET    /sub/{token}/clash.yaml         分发：mihomo 配置（附 subscription-userinfo 头）
GET    /sub/{token}/shadowrocket.conf  分发：Shadowrocket 配置
GET    /sub/{token}/clash-offline.yaml        分发：离线自包含版（规则内联，外网兜底）
GET    /sub/{token}/shadowrocket-offline.conf 分发：离线自包含版；以上分发端点均可加 ?qr 生成扫码页
GET    /rules/{file}                   分发：规则集缓存（.yaml/.list）
GET    /api/mirror                     镜像推送配置与状态（提供方、最近推送、公网 URL）
POST   /api/mirror                     {provider: cf-kv|github, credentials, enabled} 保存并立即试推
POST   /api/mirror/push                手动推送当前产物
```

语义约定：

- 所有「变更类」操作（订阅增删改、回退）完成后自动走一遍完整链路（解析→清洗→渲染→校验→发布），客户端无需感知中间态。
- 分发端点命中时返回 `ETag`（产物 hash），客户端轮询时 304 便宜。
- 错误体统一 `{code, message}`；分发端点在**任何**后端故障下都不 5xx 空响应——永远返回上一份有效产物（见 01 安全网）。

## 3. Web UI（单页，方向性描述）

| 区块 | 内容与关键词 |
| --- | --- |
| 订阅卡列表 | 别名、流量/到期进度条（userinfo）、最近抓取状态（成功/失效/超时）、启停开关、删除 |
| 节点总表 | 按地区折叠；列：名称、地区、属性徽章（家宽/专线/倍率）、所属机场、纯净度徽章；被滤节点单独折叠区 |
| 纯净度报告 | 按 Claude 适配度排序的表格：出口 IP、ASN/组织、住宅或机房、检测时间；「家宽→机房」属性变化标红；顶部给出 Claude 专用组推荐 Top3 |
| 配置产物 | 当前版本号、节点数 diff 时间线、双格式预览、订阅链接复制按钮、**离线包下载（含最近刷新时间提示）**、回退按钮 |
| 操作 | 「立即刷新全部」「扫描纯净度」「规则源状态」 |

技术方向：服务端渲染的极简单页（FastAPI + 少量原生 JS），不引前端框架。内网可信环境，无登录体系（token 保护分发链接即可）；如需登录作为 v2 可选项。

## 4. 纯净度检测引擎

### 原理

- 容器内置 **mihomo 探测实例**（独立进程，配置 `data/probe/config.yaml`，`external-controller: 127.0.0.1:9095`，混合端口仅绑 127.0.0.1），加载全部真实节点。
- 对每个节点：调用探测实例控制 API `GET /proxies/{name}/delay` 确认可用 → 经该节点作为代理发 HTTP 请求 `http://ip-api.com/json/?fields=status,country,as,asname,org,isp,proxy,hosting,mobile` → 拿到出口 IP 与属性。
- ip-api 免费额度 45 req/min：全 41 节点一轮约 1 分钟，够用；抽象出 `PurityProvider` 接口，未来可换 ipinfo/ipqualityscore 增强风险分（v2 预留）。

### 评分与分类

| 判定 | 条件 | Claude 适配度 |
| --- | --- | --- |
| 住宅宽带 | `hosting=false` 且 org 含 ISP 特征（Telecom/Comcast/Verizon/宽带商…）或命中节点名「家庭/家宽」 | ★★★ 首选 |
| 商家机房（如 DMIT） | `hosting=true`，中小 IDC | ★★ 可用 |
| 大厂云 | ASN ∈ {AWS, GCP, Azure, DO, Vultr, Hetzner, OVH, Linode…} | ★ 谨慎（滥用 IP 段易触发风控） |
| 已被标记代理 | `proxy=true` | 降权提示 |

### 调度

- 每天 04:00 全量扫描；订阅刷新发现**新增节点**时增量扫描。
- 属性变化告警：上次「住宅」这次「机房」→ UI 标红 + 建议重新锁定 Claude 节点。
- 探测实例健康：启动失败/中途崩溃 → 报告标记 unavailable，主分发链路无感；下轮调度自动重启。
- 结果只做**建议**，从不自动改写用户已手动锁定的 Claude 节点（组语义见 02 文档）。
